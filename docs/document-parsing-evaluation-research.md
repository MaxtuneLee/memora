# 文档解析准确率评估建议

核实日期：2026-09-08。本文是评估设计建议，不表示实验已经运行。

## 是否需要寻找 Markdown 论文

可以使用有人工校对参考文本的 PDF，但不必自行寻找 Markdown 版本论文。直接计算整份 Markdown 字符串的 WER/CER 容易把换行、标题符号、表格表示方式和合理的阅读顺序差异算成内容错误，也可能低估关键公式的单字符错误。olmOCR-bench 的设计说明专门讨论了这些局限，并采用可检查的事实断言。[官方说明](https://github.com/allenai/olmocr/blob/main/olmocr/bench/README.md)

建议先明确目标是“可靠提取可检索文本”。对人工确认的对应正文块，规范化 Unicode、空白和 Markdown 格式后计算 CER；英文可补 WER。不要归一化掉数字、否定词等实质内容。另记遗漏正文、阅读顺序错误和解析失败。参考文本必须独立于被评估解析器；用同一个模型生成参考答案会使测量偏向该模型。这些是针对 Memora 的方法建议。

## 可使用的数据集

| 数据集       | 输入与参考标注                                                                     | 适合测什么                                                   | 使用边界                                                              |
| ------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------- |
| OmniDocBench | 页面图片、PDF，以及 JSON 中的正文、区域坐标、阅读顺序、表格 HTML/LaTeX、公式 LaTeX | 正文识别、布局、表格、公式和阅读顺序的分项质量               | 适合需要参考正文的评估；按语言、布局和文档类型抽样                    |
| olmOCR-bench | PDF 与 JSONL 测试断言，预测提交 Markdown                                           | 文本是否保留、多栏顺序、表格单元格关系、公式结构等具体正确性 | 适合轻量通过率检查；不是逐页完整参考转写，无法直接作为完整 CER 的参考 |

OmniDocBench 当前数据卡说明 v1.6 完整集含 1,651 页，覆盖英文、简体中文、中英混合、繁体中文及其他语言类别，提供原 PDF 切片及图片。数据卡限定研究用途、非商业使用。需要固定版本和样本 ID，不能将所抽子集成绩称为完整官方基准成绩。[官方数据卡](https://huggingface.co/datasets/opendatalab/OmniDocBench)

OmniDocBench 官方评估支持正文 normalized edit distance、表格 TEDS、公式 CDM、阅读顺序 edit distance；布局检测另有 mAP/mAR。当前总分由正文、表格和公式三个分项组成。Memora 如只承诺提取可检索文本，可以先单独报告正文结果，无须将未支持的高保真表格/公式恢复新增为产品要求。[官方评估仓库](https://github.com/opendatalab/OmniDocBench)

olmOCR-bench 数据卡标注英文、ODC-BY，说明包含 1,403 个 PDF 和 7,010 条测试。类别包含旧扫描件、多栏、小字、表格和数学等；具体记录数应以固定版本文件为准。[官方数据卡](https://huggingface.co/datasets/allenai/olmOCR-bench)

其实现对文本进行格式/空白规范化，检查文本存在、缺失、相对顺序等；公式采用渲染后的结构比较。可以复用官方离线评分程序，不要求浏览器运行其完整评分依赖，也不要求使用 olmOCR 模型。[官方评分实现](https://raw.githubusercontent.com/allenai/olmocr/main/olmocr/bench/tests.py)

## 建议的最小实验

以下数量是启动实验的建议，不是统计充分性的保证。

1. 固定抽取 30–50 页：普通正文、双栏文档、扫描件各占一定比例，并覆盖实际支持的语言。可优先选 OmniDocBench 中匹配目标的样本；提前登记选择规则。
2. 浏览器运行实际解析链路，保存原文件 ID、解析输出、错误、耗时、解析方式、浏览器、硬件和模型版本。原生含文本 PDF 与扫描/OCR 路径分开报告；不要把图片转 PDF 后的成绩当作原生 PDF 文本提取成绩。
3. 第一版只报告正文 CER、解析成功率、耗时和人工复核错误类型。若直接使用官方正文评分，则沿用其 normalized edit distance 名称，避免与 CER 混称。
4. 补少量阅读顺序与关键内容断言；olmOCR-bench 可作为这一项的来源。抽子集后保留该页全部适用测试，并写明筛选方式。
5. DOCX 另准备 10–20 个来源可控的文档，覆盖段落、标题、列表和表格，由人工确认预期正文。Markdown/TXT 做读取完整性与编码验证即可，无须套用视觉 OCR 基准。旧版 DOC 已按用户决定排除。
6. 导出逐样本 JSON/CSV 和 Markdown 汇总，保留失败样本。不要只保存平均分，以便重新计分和分析错误。
