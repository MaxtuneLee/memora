# Nemotron ASR adapter bypasses local-model-runtime

The evaluation playground needs a second ASR model (NVIDIA Nemotron 3.5 ASR, a cache-aware streaming FastConformer-RNNT) alongside Whisper, selectable per evaluation run. `local-model-runtime` — the registry Whisper's manifest lives in — is built entirely around `@huggingface/transformers` pipelines, with no notion of a second inference engine; Nemotron requires raw `onnxruntime-web` session control (three separate ONNX sessions, chunked encoder execution with recurrent cache state, RNN-T greedy decoding) that doesn't fit that pipeline abstraction. Rather than build a runtime-kind abstraction into `local-model-runtime` to accommodate one model, we're adding Nemotron as a standalone `ModelAdapter` wired directly into `evaluation.shared-worker.ts`, with its own OPFS-backed weight cache (a new directory alongside `/transformers-cache`, included in `useStorageStats.ts`'s breakdown). This keeps the change scoped to the evaluation playground — nowhere else in the app (e.g. live mic transcription via `modelRouting.ts`) can select Nemotron yet. If Nemotron proves worth using for real transcription later, that's the point to build the shared runtime-kind abstraction; until then it would be speculative.

**Device selection also deviates from convention.** Every other local-model-runtime handler (`handlers/embedding.ts`, `handlers/formula.ts`, Whisper's own manifest) picks one device for the whole model: detect `navigator.gpu` once, run entirely on webgpu or fall back entirely to wasm. Nemotron's RNN-T decode loop calls the decoder+joint once per emitted token, each call depending on the previous one's output — an autoregressive chain that can't be batched, so per-call GPU dispatch/readback sync cost dominates regardless of whether audio arrives live or as a whole file (eval's batch mode still decodes one token at a time across the utterance). So Nemotron assigns devices per-session instead of per-model: the encoder follows the usual webgpu-with-wasm-fallback convention, but the decoder and joint network always run on wasm, unconditionally, even when the encoder is on webgpu.
