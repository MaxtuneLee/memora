## 6. 隐私承诺

- [x] 实现本地文件、转写结果与聊天数据存储。
- [x] 实现本地内容检索与片段返回路径。
- [x] 实现单次工具结果长度限制。
- [ ] 处理 `read_file` 默认全文读取路径，避免绕过相关片段发送设计。
  - 位置：`packages/web/src/lib/chat/tools/fileTools.ts` 的 `read_file`，未传 `offset`/`limit` 时直接返回整个文件内容。
  - 影响：聊天开启了 compaction，工具结果最多保存 100,000 字符；发给模型的请求保留前 6,000 和后 1,500 字符，其余内容模型可通过 recall 分页取回。发送的内容由文件位置决定，而不是由相关性决定，模型也可以逐页取回全文。`read_extracted_content` 默认一次返回 12,000 字符，情况相同。
  - 处理方向：`read_file` 未指定范围时只返回有限窗口，并提示先用内容搜索定位；或在论文中把“只发送相关片段”改为“默认通过检索发送相关片段，读取全文时例外”。
- [ ] 检查实际云端请求，验证基于指定文件的问答发送所需片段，并记录证据。
- [ ] 明确全文总结、完整图片附件等操作与“只发送相关片段”承诺的关系；存在例外时如实说明，不能直接视为原承诺已满足。
- [ ] 在论文中统一架构表述：存储、解析、转写和检索在本地，BYOK LLM 推理可以使用云端。

长度限制不等于相关性保证。本阶段不要求新增逐片段审批、发送前预览或 API Key 加密系统。
